# 입력·가챠·PP 보상 검증

2026-09-17, Unity 6000.3.6f1, grayling 작업 공간.

- 클릭/키 입력으로 진입하던 WebGL 자동 전체화면 제거.
- 주요 UI에 Tab/Shift+Tab 선택 이동, F 실행, Esc 뒤로가기 연결.
- 씬 전환마다 하나의 입력 시스템을 유지하고 이전 포인터 상태를 해제.
  마우스 이벤트가 터치 포인터를 지우지 않도록 입력 정책 수정.
- 최초 가챠는 무료 후보 팀 5개(각 6마리)를 서버에 저장하고 한 팀만 수령.
  이후에는 기존 가격인 한 마리당 500 PP, 1–10마리 선택 방식.
- 유료 뽑기는 영수증·수집 결과·PP 차감을 같은 DB 배치로 처리.
  응답 유실/재접속 시 같은 요청 ID를 재사용해 이중 차감 방지.
- 피격 동작이 시작될 때 HP UI를 갱신하고, 결과 화면은 마지막 연출 이후 표시.
- 포획 결과 문구는 공의 마지막 흔들림과 잠금/탈출 연출 뒤에 표시.
- PP·아이템 보상 문구에 줄바꿈과 글자 크기 조절 적용.

## 검사

- [Unity Play 검사](verification.json): 35개 통과. Battle → MainMenu → Battle
  실제 씬 전환 후 합성 터치, Tab/F 입력, HP 표시 순서, 보상 영역 검사.
- 전투 EditMode 검사: 194개 통과.
- 서버 `npm run typecheck`, `npm test`: 5개 테스트 통과.
  실제 SQLite SQL로 최초 팀 저장, 동시 선택, 잔액 부족, 중복 구매 재시도,
  PP 보상 지급과 PvP 중복 보상 거절을 검증.
- [긴 보상 문구](rewards.png), [무료 후보 팀 선택](starter_groups.png).
  화면 검사용 고정 데이터이며 실제 계정의 뽑기 결과는 아님.

기존 PP/수집 구현은 별도 작업 폴더의 `fix/audit-sweep` 소스를 읽어 필요한 부분을
가져와 연결했습니다. 해당 작업 폴더는 변경하지 않았습니다. DB 필드 이름 `coins`는
호환성을 유지하고 UI에서는 PP로 표시합니다.

## 적용 범위

로컬 코드와 Unity Editor에서 검증했습니다. 실제 휴대폰 WebGL,
네트워크 매칭 후 두 기기에서 진행하는 PvP 연속 대전은 아직 검증하지 않았습니다.
운영 반영에는 [서버 안내](../../Server/pokelab-online/README.md)에 따른 누락 DB 마이그레이션,
Worker 배포와 Unity/WebGL 재빌드가 필요합니다. 운영 서버에는 배포하지 않았습니다.
